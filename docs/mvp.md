# MVP 범위

> 실험 결과를 바탕으로 한 **제안**입니다. 팀 확인 후 확정합니다.

## 만드는 것

| 기능 | 내용 | 상태 |
|---|---|---|
| 사진 입력 | 알약이 크게 보이게 잘린 사진 한 장 | 실험 코드 있음 |
| 약 판별 | 각인 + 겉모습으로 약 목록 1,211종에서 순위 계산 | 실험 코드 있음 |
| 결과 표시 | 약 1개 / 후보 5개 이하 / 다른 면·다시 찍기 요청 | 규칙 시험 완료, 화면 없음 |
| 앞뒤 사진 | 다른 면 사진을 받아 함께 판별 | 코드 일부 (`match6c_cns.py`), 요청 흐름 없음 |

## 안 만드는 것

| 기능 | 이유 |
|---|---|
| 크기로 약 구분 | 촬영 거리를 고정하기 어려움 (2026-11-02 결정) |
| 전처리 | 개발·검증에서 효과 없음 |
| 알약 자동 자르기 | 실험에서 고르긴 했지만 약 정확도 차이가 2장뿐. 전체 사진 입력은 별도 검증 필요 |
| 복용 안내, 처방 판단 | 제안: 약 이름 판별까지만. 팀 확인 필요 |

## 알려진 한계

- 각인·모양·색이 모두 같은 약은 사진 2장으로도 가를 수 없어 후보로 보여 줍니다 (예: 아리셉트정과 아리셉트에비스정의 같은 용량).
- 원형 등 긴 알약이 아닌 약은 정확도가 낮습니다 (긴 알약 96.1%, 그 외 약 68%).
- 카메라 60°는 학습에 없던 각도입니다. 세트 A에서 60° 49.1%, 90° 68.4%였습니다 (입력 조건 차이가 섞인 숫자).
- 각인 없는 면에서 글자를 지어낼 위험은 재지 못했습니다.

## 팀 확인 필요

- 앱 형태 (웹 / 모바일)
- 사용자가 잘린 사진을 어떻게 만들지 (직접 자르기 / 촬영 안내 / 자동 자르기)
- MVP 완료 기준 숫자
